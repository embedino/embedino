## 1. Executive Summary

Embedino is an open-source, local-first, AI-powered IDE and workspace customized specifically for embedded hardware systems and microcontroller engineering. Derived from `pingdotgg/t3code`, Embedino scales to 100+ hardware features without merge fatigue by adhering strictly to the **3 Golden Rules of Upstream Resilience**:

1. **Rule 1 — The 95/5 Modular Isolation Principle**: 95%+ of custom hardware code is housed in dedicated, isolated directories never touched by upstream T3 Code.
2. **Rule 2 — Thin Docking Ports**: Interactions with upstream code occur solely through minimal, 1-to-2 line "docking ports" designed to merge cleanly during 3-way reconciliation.
3. **Rule 3 — Strict Regraft Exclusions**: Unused upstream surface area (such as mobile apps, marketing sites, and mobile CI workflows) is strictly excluded in `regraft.json` to prevent merge stalls.

This report delivers a comprehensive audit of all docking port touchpoints, the Regraft monorepo layout, directory pruning rationale, and an assessment of merge conflict risk for future upstream pulls.

## 3. Pruned Directories & Monorepo Rationale (Rule 3)

### 3.1 Pruned Components & Exclusion Rules

`regraft.json` defines explicit exclusions:
1. **`apps/mobile/**`**: Completely excluded from the `t3-apps` graft.
2. **`scripts/mobile-*`**: Excluded from the `t3-scripts` graft.
3. **Marketing Websites**: Excluded from repository root and workspace definitions.

### 3.2 Technical Rationale for Pruning

1. **Embedded Hardware Specialization**: Embedded hardware IDE operations (e.g. USB/COM port polling, WMI/udev device inspection, serial monitor baud streaming, PlatformIO/Arduino CLI subprocess spawning, and firmware flashing over USB) require deep desktop OS and local backend server capabilities. Mobile platforms (iOS / Android / React Native / Expo) lack USB serial driver access and local CLI toolchain execution.
2. **Elimination of Merge Noise**: Upstream `t3code` frequently modifies Expo 56, Metro bundler plugins, React Native native modules, and mobile CI pipelines. Excluding mobile removes thousands of lines of non-applicable upstream diffs, eliminating merge conflicts in code Embedino does not use.
3. **Build & CI Velocity**: Pruning mobile packages eliminates heavy Expo dependencies from `pnpm-workspace.yaml`, substantially decreasing `pnpm install` time, TypeScript typechecking overhead (`pnpm run tc`), and desktop build durations (`pnpm run build:desktop`).

## 4. Comprehensive Audit of Thin Docking Ports (Rule 2)

A docking port is a minimal, surgical insertion into an upstream file that establishes a link between the upstream runtime and isolated Embedino subsystems.

```

│                                 UPSTREAM T3 CODE CORE                                  │
│                                                                                        │
│  [index.ts]       [rpc.ts]          [client.ts]          [ws.ts]        [Sidebar/Chat] │
│      │               │                   │                  │                  │       │

│                           EMBEDINO DEDICATED DOMAIN (95%)                              │
│                                                                                        │

│  apps/server/src/hardware/* apps/web/src/state/*         apps/web/src/components/*    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 6. The Dedicated 95% Architecture

## 7. Conclusions & Strategic Recommendations

1. **Architecture Resilience**: Embedino's architecture conforms strictly to Rules 1, 2, and 3 of `AGENTS.md`. The minimal blast radius of docking ports ensures smooth upstream synchronization via `regraft pull`.
2. **Expansion Playbook for Future Features (Serial Monitor, Pinout Canvas, Datasheet Reader)**:
   - When adding the Serial Monitor: Create `apps/server/src/hardware/SerialMonitorService.ts`, `apps/web/src/state/serial.ts`, and `apps/web/src/components/hardware/SerialMonitorView.tsx`.
   - Docking: Only touch `rpc.ts` (add `hardwareSerial*` RPCs) and `ws.ts` (delegate to `SerialMonitorService`).
   - Never add business logic inside upstream files.
3. **Regraft Protocol Compliance**: Always run `regraft note "<description>"` whenever new docking points are introduced.
